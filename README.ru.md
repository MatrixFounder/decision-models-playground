# Decision Models Playground

[English](README.md) | **Русский**

Локальный стенд для decision-моделей: один звонок и одни вопросы прогоняются через несколько моделей сразу, ответы
(вероятности, задержка, цена, снимок модели) ложатся рядом. Плюс локальный сервер `POST /v1/systemone`, через который
стенд whip-insight подключает d1-модели, работающие на Mac.

> **Статус (2026-11-09).** Инкременты P0–P6 выполнены ([TASK 001](docs/TASK.md)):
>
> - Workbench, история и дневной бюджет с облачными моделями OpenRouter и локальными d1 (MLX);
> - compat-сервер `/v1/systemone` для whip-insight;
> - проба возможностей и матрица «модель × возможность»;
> - размеченные наборы (теги whip-insight, синтетика, свои файлы) с отчётом калибровки и порогом для тега
>   whip-insight;
> - эксперименты на устойчивость (формулировки, порядок вариантов, повторы);
> - режимы: указатель по репликам, извлечение с RU-нормализацией, `multi` с порогом, аудио для d1-Omni.
>
> Дальше — движок `systemone_http` (Ollama, llama.cpp) и LLM-базовая линия: work-item
> [WI-1](docs/backlog/wi-1-p7-systemone-http-and-llm-baseline.md) в [бэклоге](docs/BACKLOG.md).

## Что это и зачем

Decision-модель (Jev от TypeSafe, d1 от Liquid AI, Microsoft-Decision-1 и другие) отвечает на закрытые вопросы
вероятностями и не генерирует текст. Чтобы решить, какой модели доверить смысловые теги, тип разговора или проверку
звонка в whip-insight, их нужно сравнивать на своих звонках, на русском, с измеренными порогами.

Четыре задачи первой версии:

1. **Сравнение и калибровка.** Вероятности разных моделей бок о бок; формулировки RU/EN, порядок вариантов, повторы;
   кривая «порог → покрытие и точность» на размеченном наборе.
2. **Локальный рантайм для whip-insight.** d1-2B и d1-Omni-2B на Apple Silicon через `mlx-vlm` отдаются наружу как
   `POST /v1/systemone` (порт 8791, bearer-токен). LM Studio эту роль не тянет: он не загружает `lfm3_omni` и
   запускает модели через генерацию текста.
3. **Новые возможности d1.** Аудио на входе (тип звонка по записи), извлечение дат, сумм и номеров со `span`, выбор
   нескольких вариантов.
4. **Decision против LLM.** Тот же вопрос через обычную LLM на OpenRouter: согласие, цена, задержка (WI-1).

## Движки

| Движок | Модели | Где работает | Статус |
|---|---|---|---|
| `openrouter_decisions` | `typesafe/jev-1.14`, `liquid/d1.1`, `~liquid/d1-latest` и другие из каталога | OpenRouter Decisions API, ZDR по умолчанию | готов |
| `mlx_local` | `LiquidAI/d1-2B-MLX-8bit`, `LiquidAI/d1-Omni-2B-MLX-8bit` | в процессе на Mac, `mlx-vlm >= 0.7.11`, одна модель в памяти | готов |
| `systemone_http` | Ollama `d1`, `d1:2b`; `llama-server` с d1-3B-GGUF; свой compat-сервер | локальные серверы с `/v1/systemone` | план (WI-1) |
| `openrouter_llm` | список LLM в `config.yaml` | OpenRouter chat completions; `logprobs` или словесная уверенность | план (WI-1) |

Запланированные виды можно оставить в `config.yaml`: реестр покажет их недоступными.

## Что нужно

- macOS на Apple Silicon для локальных моделей (`make setup` ставит `requirements-mlx.txt` только там). UI,
  compat-серверу и облачным движкам хватает `requirements.txt`; см. [Другие платформы](#другие-платформы).
- Python 3.14 (Makefile берёт pyenv 3.14.8, иначе `python3` из `PATH`). Всё ставится в `.venv` проекта.
- Ключ OpenRouter для облачных движков.
- `ffmpeg` для загрузки аудио (`brew install ffmpeg`).
- Node.js для тестов фронтенда (необязательно: без `node` `make test` их пропускает).
- Около 4.6 ГБ на диске для двух 8-bit MLX-моделей; 16–24 ГБ памяти.

## Другие платформы

Плейграунд сделан и проверен на macOS с Apple Silicon. На других платформах он работает в урезанном виде.

| Платформа | Работает | Не работает |
|---|---|---|
| macOS, Apple Silicon | всё | — |
| macOS Intel, Linux | UI, `/api`, облачные движки (`openrouter_decisions`); Workbench, История, Наборы, Эксперименты, Матрица, указатель на облачных движках | локальные d1, см. ниже |
| Windows (нативно) | ничего: не поддерживается | использовать WSL2, там действует строка Linux |

На macOS Intel и Linux:

- `make setup` не ставит `requirements-mlx.txt`. Движки `mlx_local` видны, но недоступны: «needs macOS on Apple
  Silicon».
- Compat-сервер запускается, но отдавать ему нечего: `POST /v1/systemone` отвечает 503 `model_unavailable`,
  `GET /health` — `unavailable`. whip-insight его использовать не сможет.
- Недоступно то, что умеют только локальные d1: аудио (слышит только d1-Omni; загрузка и конвертация работают),
  извлечение (`text`, `number`, `date`) и `multi`. OpenRouter такие типы вопросов отклоняет.
- Не запускать `make models`, `make smoke-local`, `make spike-mlx`: им нужен стек MLX. `make spike-audio` требует
  команду macOS `say`.
- `make test` пропускает ~98 тестов локального движка, которым нужен mlx-vlm, и пишет об этом в последних строках.
- Надёжная запись идёт через `fsync` вместо `F_FULLFSYNC` macOS. Адрес compat-сервера на экране «Локальные модели» —
  имя хоста плюс `.local`; на Linux для mDNS нужен Avahi.

Windows: `app/store.py` импортирует `fcntl` (только POSIX), остановка использует `loop.add_signal_handler`, а Makefile
требует `make`, POSIX-оболочку и `lsof`.

**Как проверено.** Только симуляцией на Mac: один `requirements.txt` и `platform.machine()`, возвращающий `x86_64`.
Приложение импортируется; pytest — 773 прошло, 98 пропущено из-за mlx-vlm, 0 упало. На настоящих Linux, Intel Mac и
Windows ничего не запускалось.

## Быстрый старт

```bash
make setup     # .venv, зависимости (+ requirements-mlx.txt на Apple Silicon), .env и config.yaml из примеров
$EDITOR .env   # OPENROUTER_API_KEY; права 600
make models    # скачать d1-2B и d1-Omni (8-bit MLX, ~4.6 ГБ) в HF_HOME
make check     # какие движки готовы, каталог, расход за сегодня
make run       # UI http://127.0.0.1:8790 и compat-сервер :8791
make test      # тесты без сети, ключей и моделей
```

## Как пользоваться

Пошаговая работа с каждым экраном — в [руководстве пользователя](docs/manuals/user-guide.ru.md).

- **Workbench.** Вставить звонок (или выбрать пресет), задать вопросы, отметить движки, «Запустить». Оценка стоимости
  видна до запуска, расход за день — в шапке. Черновик (транскрипт и вопросы) переживает перезагрузку страницы.
- **История и ссылки.** `/?run=<id>` открывает прогон, `/?compare=<id1>,<id2>` сравнивает два, `/?report=<id>`
  открывает отчёт набора или эксперимента, `/?tab=history` — историю.
- **Локальные модели.** Одна в памяти, выгружается через 10 минут простоя или кнопкой на экране «Локальные модели».
- **Наборы.** `make import-tags` превращает 56 стандартных тегов whip-insight в пресеты вопросов и размеченные наборы
  из их тестовых фраз (`WHIP=../whip-insight`), `make synth TAG=std_answering_machine` ставит фразы в нейтральные
  диалоги. На экране «Наборы» — прогон по движкам с оценкой стоимости и отчёт: порог для тега whip-insight, кривая
  «покрытие ↔ точность», диаграмма надёжности, расхождения. Свой набор — файл JSONL или CSV с метками.
- **Эксперименты.** Кнопка «Эксперимент…» в Workbench отправляет текущий звонок и вопросы на экран «Эксперименты»: те
  же вопросы в других формулировках (например, по-английски), с вариантами в других порядках и по N раз. Отчёт: размах
  повторов, сдвиг вероятностей от порядка и формулировки, тяга к первому варианту, тепловая карта.
- **Указатель по репликам.** Галочка в Workbench. Строка транскрипта — реплика, «Имя: текст» — участник. После «да» и
  для лучшего варианта модель показывает реплику-доказательство (как указатель whip-insight); она подсвечена под
  ответом с вероятностью. Проходы указателя платные и входят в оценку.
- **Извлечение** (`text`, `number`, `date`, локальные d1). Найденный фрагмент подсвечен в тексте звонка. Если модель
  нашла «12 ноября 2026 года» или «триста пятьдесят тысяч рублей», но не дала значения, плейграунд читает фрагмент
  сам и помечает: «нормализовано плейграундом». У `multi` — порог и выбранные варианты.
- **Аудио и картинки.** Кнопка «Медиа…» принимает запись (WAV, MP3, M4A, OGG, FLAC, WebM, AMR) и переводит её в WAV
  16 кГц моно, первые 30 секунд (`audio.max_seconds`); картинки — PNG, JPEG, WebP. Загрузки лежат в `media/`,
  удалить — `make clean-media`. Слышит только d1-Omni; пресет «Тип звонка» (`call_kind`) — вопрос «человек,
  автоответчик, IVR…». Синтезированную речь модель слышит как робота: точность проверяется на настоящих записях.
- **Матрица.** Кнопка «Проба» в строке движка проверяет, какие типы вопросов, сколько вариантов и уровней модель
  обслуживает, по тем же запросам, что whip-insight. Галочка «длинный» добавляет проверку чтения всего контекста:
  перед ней экран покажет оценку стоимости. Прогоны сразу берут профиль из пробы: вопрос, который модель не
  обслуживает, не отправляется.
- **Compat-сервер для стенда whip-insight.** В `.env` задать `SYSTEMONE_TOKEN` (≥ 32 символа, например
  `openssl rand -hex 24`) и `COMPAT_HOST=0.0.0.0`; без токена сервер слушает только этот Mac. Проверка:

  ```bash
  curl -s http://127.0.0.1:8791/v1/systemone -H "Authorization: Bearer $SYSTEMONE_TOKEN" \
    -H 'Content-Type: application/json' -d @tests/fixtures/requests/whip_insight_systemone.json
  ```

## Команды make

| Команда | Что делает |
|---|---|
| `make setup` | Создать `.venv`, поставить зависимости (+ MLX на Apple Silicon), создать `.env` и `config.yaml` из примеров |
| `make models` | Скачать две 8-bit MLX-модели в `HF_HOME` |
| `make run` / `make run-compat` | UI и compat-сервер на переднем плане / только compat-сервер |
| `make run-bg` / `make stop` | То же в фоне (журнал `/tmp/decision-playground.log`) / остановить |
| `make check` | Доступность каждого движка, кэш каталога, расход за сегодня |
| `make test` | Тесты Python и фронтенда (без сети, ключей и моделей) |
| `make smoke-local` | По желанию: настоящий локальный путь, грузит d1-2B и d1-Omni, журнал в `docs/reviews/` |
| `make import-tags` | 56 стандартных тегов whip-insight → `presets/std_tags/` и `datasets/` (`WHIP=../whip-insight`) |
| `make synth` | Фразы тега в нейтральных диалогах → `datasets/synth_<tag>` (`TAG=…`) |
| `make clean-runs` / `make clean-media` | Удалить `runs/` / `media/` (с вопросом) |
| `make spike` | Спайк P0: OpenRouter и обе локальные d1 ([SPIKE.md](docs/SPIKE.md)) |

## Настройка

- `.env` — ключи, адреса и порты, `HF_HOME`, `DAILY_BUDGET_USD` (по умолчанию 1 USD), `FFMPEG_BIN`, `DATA_DIR`.
  Шаблон с комментариями — [.env.example](.env.example).
- `config.yaml` — реестр движков, менеджер локальных моделей, лимиты compat-сервера, аудио, оценка стоимости. Шаблон
  с комментариями — [config.example.yaml](config.example.yaml).
- UI и `/api` — только `127.0.0.1:8790`. Compat-сервер — `:8791`, в LAN только с `SYSTEMONE_TOKEN`.
- Бюджет: дневной лимит платных вызовов, оценка перед каждым прогоном.

## Данные и лицензии

- Реальные звонки остаются на диске в `runs/` и `datasets/` (оба в `.gitignore`); в OpenRouter уходят с ZDR и
  `data_collection: deny`. Модель без ZDR-эндпоинта вызывается только с согласием на один прогон.
- Черновик Workbench (транскрипт и вопросы) браузер хранит в `localStorage`, чтобы пережить перезагрузку; это копия
  звонка вне `runs/`, и `make clean-runs` её не удаляет.
- В отчётах нет текстов звонков: только id, метки, вероятности и метрики.
- Открытые d1 — LFM Open License v1.0: коммерческое использование разрешено при годовой выручке компании меньше
  $10 000 000. Владелец разрешил их 2026-11-08; на новой инсталляции условие проверяется заново.

## Связь с whip-insight

Плейграунд ничего не пишет в whip-insight. Связи:

- **Compat-сервер.** Он становится dev-профилем whip-insight (строка `cvj.decision_configs`), это отдельный
  work-item whip-insight после task-049.
- **Пресеты.** Скрипт импорта читает файлы тегов из репозитория whip-insight.
- **Находки.** Пороги и правила формулировок владелец переносит в замеры `SPEC-decision-service.md` §15.

# VDD Critique: P2 — `mlx_local`, local model manager, compat server `/v1/systemone`

## 1. Executive Summary
- **Verdict**: WARNING. There are no CRITICAL findings, but four HIGH findings stand (security and memory), so this is **not an approval**. Reject until the HIGH findings are fixed.
- **Confidence**: High. Every HIGH finding was reproduced in a throwaway copy. Two of them were confirmed against the installed mlx-vlm and transformers code. The token counts come from the real d1-2B tokenizer; no model was loaded.
- **Summary**: The manager's lock, eviction and single MLX thread hold up under single cancellation, and the startup refusal in §9.2 is sound. The compat server's request checks have holes, though, and an authenticated LAN caller can get past every memory and file guard:
  - `instructions` given as a media dict reaches mlx-vlm as a file path or URL. That is a local file oracle, a fetch with no timeout that hangs the MLX thread, and an SSRF.
  - `images` accepts EPS and runs Ghostscript on the caller's bytes.
  - A dict state is counted in compact JSON, but mlx-vlm renders it with `indent=2`: a state that passes both checks at 16K tokens reaches the model as 126K tokens.
  - Question text is not bounded at all.

  Planted regressions show that the compat error contract, `MlxBackend`/`SnapshotDates` and the lifecycle code (`aclose`, watcher, `__main__`) have no test that goes red.

### Checked and found sound

- **Auth and Origin**: the token is compared in constant time and checked before the body is read. The Origin rule refuses browser POSTs, including after DNS rebinding.
- **Manager**: FIFO lock and eviction, one MLX thread, and survival of a single cancellation while queued, loading or calling.
- **Contract**: answers in System One names; `score` as the weighted level (`score_readout="mean"`); `usage` shape; dated snapshot.
- **UI**: no XSS (`el` writes only text nodes), and the token never reaches the UI.

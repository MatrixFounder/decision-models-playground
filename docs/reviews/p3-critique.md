## 1. Executive Summary
- **Verdict**: WARNING. There is no CRITICAL finding. Five MEDIUM and 27 LOW findings remain, so this is not an approval.
- **Confidence**: High. Each behaviour below was reproduced by an experiment test or a planting in the plant copy. Nothing went to the network, and no model was loaded.
- **Summary**: The reading table, the size rule and the SSE contract match whip-insight on the paths the tests cover. Both suites are green (pytest 474 passed, 1 skipped; node 21/21). The gaps are at the edges of the rule and in what the tests guard:
  - **Faithfulness (MEDIUM).** `no_profile` is keyed on "some request was *served*", where whip-insight's rule is "some request got a *2xx*". A probe on which every answer comes back 200 but cannot be read keeps the old full profile. whip-insight would write `types: []` (E2).

    - A successful probe narrows the run filter from 255 to 240 options with no evidence (E3). P0 measured 255 as served on both cloud models.

After a snapshot change, `reads_full_context` is copied into the new snapshot's file although it was never measured there (E15).
  - **Budget (MEDIUM).** An exception between the first paid call and `store.save` is neither saved nor charged. `engine.run` is called without the runner's guard (E1: 3 paid calls, then `spent_usd 0`, `reserved_usd 0`, and no record).
  - **Tests (MEDIUM).** The tests do not guard the overlay's core promise "a probe can confirm or narrow, never widen". Removing the intersection with the kind's ceiling (P2), the cap on the limits (P3), or the audio rule (P4) leaves the whole suite green. So does breaking whip-insight's rule "a type's own request, unobserved, keeps the stored value" (P1). Of 21 Python plantings, 18 stayed green, including the cloud `http_status` that feeds the 400 reading (P12), every LONG mechanic, both budget paths (the unsaved charge and the outer release), and the `probe_error` path.

## 1. Перед началом

Первый запуск (подробнее — README, «Быстрый старт»):

| Шаг | Команда | Результат |
|---|---|---|
| 1 | `make setup` | `.venv`, зависимости, `.env` и `config.yaml` из примеров |
| 2 | правка `.env` | `OPENROUTER_API_KEY` для облачных движков; права файла 600 |
| 3 | `make models` | d1-2B и d1-Omni (8-bit MLX, ~4.6 ГБ) в `HF_HOME`; только Apple Silicon |
| 4 | `make check` | доступность каждого движка, кеш каталога, траты за сегодня |
| 5 | `make run` | UI на <http://127.0.0.1:8790>, compat-сервер на `:8791` |

Сервер останавливается по Ctrl+C в терминале `make run`. `make run-bg` запускает его в фоне (лог
`/tmp/decision-playground.log`), `make stop` останавливает.

`.env` и `config.yaml` читаются один раз, при старте. После любой правки в них перезапустите сервер.

В шапке каждого экрана:

- вкладки шести экранов;
- плашка бюджета «Сегодня: $потрачено / $лимит»;
- кнопка языка. Интерфейс открывается на русском, «EN» переключает на английский. Выбор хранится в браузере.

## 3. Workbench: один звонок через несколько движков

### 3.1 Состояние

Левая колонка — состояние (state): текст звонка или JSON.

- «Текст» / «JSON» переключает режим ввода. Текст уходит строкой. JSON уходит объектом, например
  `{"fragments": [...]}` из whip-insight.
- «Пресет…» загружает готовые state и вопросы: `demo_bank_call` (noul, choice, score), `demo_extraction` (multi,
  text, number, date), `call_kind` (вид звонка по аудио), 56 тегов whip-insight `std_*` после `make import-tags`.
- «Файл…» загружает `.txt`, `.md` или `.json`.
- «Медиа…» прикрепляет запись или картинку (§3.8).
- Строка под полем показывает число символов.
- Черновик (state и вопросы) хранится в браузере и переживает перезагрузку страницы. Если открытый прогон заменил
  черновик, «↶ вернуть черновик» возвращает его.

### 3.2 Вопросы

«+ вопрос» добавляет вопрос, «JSON» переключает список в редактирование JSON. У вопроса есть ключ, тип и текст «Вопрос
модели».

| Тип | Что возвращает модель | Поля редактора | Движки |
|---|---|---|---|
| `noul` | P(true) | «Да — это значит…», «Нет — это значит…» | все |
| `choice` | вероятность каждого варианта, лучший вариант | id варианта + описание, «+ вариант» | все |
| `score` | вероятность каждого уровня, ожидаемый уровень | уровни, «+ уровень» | все |
| `multi` | P(да) для каждого варианта | как у `choice` | только локальные d1 |
| `text` | фрагмент state со `span` | — | только локальные d1 |
| `number` | число, `span`; с диапазоном — интервал p10–p90 | от, до, шаг, единица | только локальные d1 |
| `date` | дата ISO, `span` | — | только локальные d1 |

Правила:

- Ключ и id варианта соответствуют `^[a-z][a-z0-9_]{0,63}$`: первая — строчная латинская буква, дальше буквы, цифры,
  `_`.
- `choice`: 2–255 вариантов; `score`: 2–10 уровней.
- Повтор ключа или id варианта отмечается под редактором; прогон не запускается.
- Формат JSON — decision/1: `{"<ключ>": {"type", "instructions", "criteria"}}`. `multi` — это
  `"type": "choice", "multiple": true`. Пример: `presets/demo_extraction.yaml`.

### 3.3 Движки

Правая колонка — движки из `config.yaml`. Плашки движка:

| Плашка | Значение |
|---|---|
| `$0.02/M вх.` | цена входа за миллион токенов из каталога OpenRouter; `$?`, если цены в каталоге нет |
| `ZDR` / `нет ZDR` / `ZDR ?` | у модели есть endpoint Zero Data Retention / нет / неизвестно |
| `⌛ <дата>` | срок снятия модели по каталогу |
| `локально` | локальная модель, бесплатно |
| `выгружена` / `загружается` / `в памяти` / `занята` | состояние локальной модели (§8) |

Движки, которые не могут работать, свёрнуты под «Недоступны (n)» с причиной (§12.1). «↻» обновляет каталог
OpenRouter: цены, ZDR, сроки.

### 3.4 Запуск

1. Отметьте движки.
2. По желанию: «Название прогона» и «теги через запятую». По тегам фильтруется История.
3. По желанию: «Указатель по репликам» (§3.6).
4. Проверьте оценку: «Оценка $x · осталось $y». Она красная, если больше остатка дня.
5. Нажмите «Запустить».

Если выбран движок без ZDR, появляется «Разрешить движки без ZDR». Без этой галочки прогон не запустится. Галочка
сбрасывается после старта: каждый прогон спрашивает заново.

Результаты приходят по мере готовности каждого движка. Закрытая вкладка не останавливает прогон: он завершится и
сохранится в Истории.

### 3.5 Как читать результаты

В таблице строка — вопрос, столбец — движок.

- Ячейка показывает вероятности полосами и лучший ответ.
- Под ключом вопроса — тип и, если ответов два и больше, плашка «согласие» (все движки дали один лучший ответ) или
  «расходятся».
- Ячейка без ответа называет класс: `unsupported` (движок не обслуживает этот тип), `refused`, `invalid_answer`,
  «запрос: <класс>» (упал весь запрос этого движка). Классы — §12.2.

Строки внизу, по движку:

| Строка | Содержание |
|---|---|
| Статус | `ok`; `partial` (часть вопросов без ответа); `failed` (ответов нет); или класс отказа запроса |
| Задержка | вызов модели; у локальной — без очереди и загрузки |
| Цена | USD; подсказка: «по ответу» (от провайдера) или «по прайсу» (токены × цена каталога) |
| Токены | входные / выходные токены вызова |
| Снимок | датированная версия модели, которая ответила, например `liquid/d1.1-20261027` |

Строки под таблицей дают подробности ошибок движка.

### 3.6 Указатель по репликам

Указатель находит реплику транскрипта, на которую опирается ответ, как маршрут whip-insight.

- Формат транскрипта: непустая строка — реплика `t0, t1, …`; «Имя: текст» называет участника. Строка «Имя:» без
  текста называет участника следующей строки. Номера и таймкоды VTT/SRT становятся репликами.
- После «да» у `noul` и для лучшего варианта `choice` / `score` модели задаётся вопрос «В какой реплике …?». Ответ —
  под ячейкой: «↳ t6 Клиент: …» с вероятностью; реплика подсвечена.
- До B реплик — один вызов, больше — два прохода. B = min(240, максимум вариантов движка). Больше B² реплик — запрос
  этого движка не отправляется (`too_long`).
- Проходы оплачиваются и входят в оценку.
- С медиа указатель не работает (400).
- «“да” после округления»: P(true) в [0.4995, 0.5). Ячейка показывает «нет», а маршрут whip-insight округляет до
  0.500, читает «да» и спрашивает указатель.

### 3.7 Извлечение и `multi`

Типы `text`, `number`, `date` и `multi` работают только на локальных d1; облачные движки показывают `unsupported` без
вызова.

- Найденный фрагмент (`span`) подсвечивается в тексте звонка, если state — текст.
- Если модель нашла фрагмент, но не дала значения, плейграунд читает фрагмент сам и помечает чтение «нормализовано
  плейграундом». Он читает русские даты («12 ноября 2026 года», `12.11.2026`) и числа с пробелами или словами
  («триста пятьдесят тысяч рублей»). Значение модели никогда не заменяется.
- У `multi` под ключом вопроса есть поле «порог» (по умолчанию 0.5). Оно меняет только чтение ответа и в модель не
  уходит.

### 3.8 Аудио и картинки

- «Медиа…» принимает аудио (WAV, MP3, M4A, OGG, FLAC, WebM, AMR) и картинки (PNG, JPEG, WebP) до 16 МБ.
- Аудио переводится в WAV 16 кГц моно, первые 30 секунд (`audio.max_seconds` в `config.yaml`, до 600). Плашка
  показывает «первые 30 с из 95 с», если запись обрезана. Нужен ffmpeg.
- Аудио слышит только d1-Omni (`mlx-d1-omni`). Другие движки при аудио в запросе не вызываются.
- С медиа и пустым текстом state уходит как `null`.
- Вид звонка на слух: пресет `call_kind` + `mlx-d1-omni`. Синтезированную речь модель слышит как `voice_robot`;
  точность проверяйте на настоящих записях.
- Загрузки лежат в `media/`; `make clean-media` их удаляет.

## 4. История

- Фильтры: тег и движок.
- Столбцы: когда, название, движки, вопросы, цена.
- «Открыть» загружает прогон Workbench в Workbench. Запись набора или эксперимента открывает свой отчёт.
- «Повторить» повторяет прогон Workbench с теми же входами и движками. Сначала показывает оценку и отдельно
  спрашивает согласие на движки без ZDR. Пробы, наборы и эксперименты отсюда не повторяются.
- Отметьте два прогона и нажмите «Сравнить выбранные»: таблица покажет P лучшего варианта прогона A в обоих прогонах
  и Δ.

## 5. Эксперименты: формулировки, порядок вариантов, повторы

Эксперимент меряет устойчивость ответов.

1. В Workbench задайте state и вопросы и нажмите «Эксперимент…». Экран «Эксперименты» берёт копию; «↻ Взять из
   Workbench» берёт её заново.
2. «Формулировки»: вопросы Workbench — базовая формулировка. «+ формулировка» добавляет до пяти других как JSON тех же
   вопросов: те же ключи, типы и id вариантов, то же число уровней. Пример — английская формулировка.
3. «Порядок и повторы»: «менять порядок вариантов (choice, multi)», `k` порядков (по умолчанию 6), `seed` (по
   умолчанию 7), число повторов (по умолчанию 5, 1–20). При 4 вариантах и меньше берутся все порядки.
4. Отметьте движки и подтвердите оценку. Один эксперимент — не больше 2 000 вызовов.

Совет: в одном эксперименте меняйте порядок у одного вопроса `choice`. При нескольких таких вопросах порядки меняются
вместе, и эффект одного вопроса включает перестановку другого.

Метрики отчёта:

| Метрика | Значение |
|---|---|
| Размах повторов | max − min P по повторам одного запроса |
| SE разности | уровень шума; \|ΔP\| меньше примерно двух SE — шум |
| Порядок \|ΔP\|, Порядок: смена | сдвиг вероятности и доля смен лучшего ответа из-за порядка вариантов |
| Первый показанный (ожидаемо) | как часто побеждал вариант, показанный первым; в скобках — значение модели без тяги к первому месту |
| Подъём первого | насколько растёт вероятность варианта, когда он первый; без тяги около 0 |
| Формулировка \|ΔP\|, Формулировка: смена | то же для формулировки |

Тепловая карта показывает вероятности по движку. «Markdown» выгружает отчёт. «↺ Те же настройки» переносит state,
формулировки, порядки, повторы и движки в новый эксперимент. Если дневной бюджет кончился на середине, отчёт строится
по спрошенным ячейкам.

## 6. Наборы: калибровка порога

Набор — звонки с метками. Его отчёт даёт порог для тега whip-insight.

### 6.1 Источники

- `make import-tags` (`WHIP=../whip-insight`): 56 стандартных тегов whip-insight становятся пресетами
  `presets/std_tags/` и наборами из их тестовых фраз.
- `make synth TAG=std_answering_machine`: фразы тега внутри нейтральных диалогов, `datasets/synth_<тег>`.
- Свой файл, «Импорт файла» на экране «Наборы»:
  - JSONL: строка `{"id", "state", "labels": {"<вопрос>": "true"}, "meta"}`;
  - CSV: столбцы `state`, `id`, `label` (один вопрос) или `label:<вопрос>`; разделитель `,`, `;` или табуляция;
  - вопросы: пресет или свой JSON;
  - источник меток: «размечено вручную» или «тестовые фразы»;
  - «заменить существующий набор» перезаписывает набор с тем же именем.

Метки: `noul` — true/false (также yes/no, да/нет, 1/0); `choice` — id варианта; `score` — номер или текст уровня.
`multi`, `text`, `number`, `date` меток не принимают. Не больше 5 000 элементов; до десяти ошибок меток приходят
сразу.

### 6.2 Прогон

1. Выберите набор слева; экран покажет первые элементы.
2. Отметьте движки; «Первые» ограничивает число элементов.
3. «Запустить» показывает число вызовов, оценку и остаток бюджета и просит подтверждения.

Локальные движки идут по одному вызову и друг за другом. Если бюджет кончился, платные элементы получают `budget` и
не спрашиваются; локальные продолжаются.

### 6.3 Как читать отчёт

| Столбец | Значение |
|---|---|
| t whip-insight | порог с наибольшим согласием: вердикт «да» при P(true) ≥ t; этот t переносится в тег whip-insight |
| Согласие | доля вердиктов, совпавших с меткой, среди ответивших |
| Точность «да», Полнота «да» | для вердикта «да» при t whip-insight |
| t по цели | наименьший t, при котором точность решённых достигает цели (по умолчанию 0.90) |
| Покрытие | доля решённых элементов: max(p, 1 − p) ≥ t |
| Точность решённых | доля верных ответов среди решённых |
| Top-1 | для `choice` / `score`: доля лучших ответов, равных метке |

- «Цель» меняет целевую точность (0.50–0.99) и пересчитывает отчёт.
- Графики: кривая порога (покрытие ↔ точность) и диаграмма надёжности. Точки на диагонали: вероятности
  совпадают с долей верных ответов.
- «Расхождения (n)» — элементы, где ответ и метка разошлись.
- Для `choice` / `score` есть матрица ошибок.
- «Markdown» и «JSON» выгружают отчёт; файлы лежат и в `reports/`. В отчётах нет текстов звонков.

Порог из набора — отправная точка. whip-insight спрашивает тег по фрагментам после лексического правила, а набор
спрашивает каждый элемент целиком.

## 7. Матрица: что умеет каждый движок

Матрица показывает движки из конфигурации, затем модели каталога OpenRouter, которых нет в `config.yaml`.

### 7.1 Столбцы

| Столбец | Содержание |
|---|---|
| `noul` … `date`, `audio` | `✓` есть, `✗` нет, `?` не проверено, `—` невозможно для этого вида движка |
| ≤ вариантов, ≤ уровней | наибольший обслуженный размер `choice` и `score` |
| весь контекст | ✓, если длинная проба нашла факт в конце state размером ~90 % контекста; подсказка даёт токены |
| Контекст | предел контекста в токенах: из каталога у облачной модели, `context_tokens` у локальной (§8.2) |
| $/M вх., ZDR, Срок | из каталога OpenRouter |
| usage.cost | сообщает ли провайдер цену |
| Снимок | датированная версия, которую видела проба |
| Проба | дата и цена последней пробы; кнопка «Проба» и галочка «длинный» |

### 7.2 Проба

«Проба» шлёт короткие синтетические запросы: три базовых типа, `choice` на 24, 100 и 240 вариантов, `score` на 10
уровней; у локальных d1 ещё `multi`, `text`, `number`, `date` и аудио у d1-Omni. Профиль сохраняется в `probes/`.
Следующие прогоны сразу его учитывают: вопрос, который движок не обслуживает, не отправляется.

- «длинный» добавляет проверку чтения всего контекста. На локальной модели это медленно, на облачной стоит денег;
  экран сначала показывает оценку.
- Проба локальной модели занимает её: запросы compat-сервера ждут в очереди.
- «устарел» помечает профиль другой версии модели или модели, которая позже ответила новым снимком. Повторите пробу.
- «Обновить каталог» перечитывает цены, ZDR и список каталога.

## 8. Локальные модели

### 8.1 Экран «Локальные модели»

| Столбец | Содержание |
|---|---|
| Движок, Модель | id движка и репозиторий Hugging Face |
| Состояние | `выгружена`, `загружается`, `в памяти`, `занята`; или `недоступна` с причиной |
| На диске | размер модели в `HF_HOME` |
| Снимок | `<repo>-<YYYYMMDD>` по дате ревизии; без сети — без даты |
| Память MLX | память загруженной модели |
| Последний вызов, Вызовов | время последнего вызова и их число с момента старта |
| Выгрузить | освобождает память сразу |

Поведение:

- В памяти одна модель. Вызов другой модели выгружает текущую и загружает нужную; вызов ждёт загрузки.
- Простаивающая модель выгружается через 600 с (`local.idle_unload_s` в `config.yaml`).
- Вызовы локальной модели — из UI и из compat-сервера — идут по одному через одну очередь. Если ждут больше 8
  (`local.max_waiting`), следующий получает `rate_limited` в UI и 429 `busy` на compat-сервере.
- `timeout_s` движка (по умолчанию 30) ограничивает ожидание в очереди. Вызов, который уже идёт на MLX, не
  прерывается.

Нижняя часть экрана описывает compat-сервер (§9).

### 8.2 Контекст локальной модели

**Что это.** `context_tokens` у движка `mlx_local` в `config.yaml` — предел промпта в токенах. По умолчанию 32 768 и у
d1-2B, и у d1-Omni.

**Где посмотреть.**

- Матрица, столбец «Контекст»: текущий предел.
- Матрица, столбец «весь контекст»: прочитала ли модель state размером ~90 % этого предела; подсказка даёт токены
  проверки (29 445 при 32 768).
- `curl -s http://127.0.0.1:8790/api/local/models`: поле `context_tokens` у каждого локального движка.
- Workbench, строка «Токены»: сколько входных токенов занял конкретный вызов.

**Как работает предел.** До очереди плейграунд считает запрос токенизатором модели: state так, как его рендерит
mlx-vlm, плюс самая тяжёлая группа вопросов, плюс запас на каждую картинку и аудиоклип. Запрос больше предела получает
`too_long` в UI и 413 на compat-сервере, модель не вызывается. State, у которого рендер длиннее 16 × `context_tokens`
символов, отклоняется до подсчёта.

Предел — собственная проверка плейграунда. Модель принимает больше: в её `config.json`
`max_position_embeddings = 128000`, карточка обещает надёжное чтение до ~64K токенов. Предел нужен из-за памяти: она
растёт примерно как квадрат длины. Замеры d1-Omni на Mac с 24 ГБ в P0 ([SPIKE §2.4](../SPIKE.md)):

| Токенов | Время | Пик памяти |
|---|---|---|
| 1 781 | 0.9 с | 3.3 ГБ |
| 6 933 | 3.9 с | 3.4 ГБ |
| 13 877 | 9.8 с | 4.0 ГБ |
| 27 765 | 27.6 с | 6.1 ГБ |
| ~64K | не запускалось | прогноз ≈ 20 ГБ |

d1-2B даёт примерно то же время и на 0.5 ГБ меньше памяти. Русский диалог — около 2.6 символа на токен, поэтому
32 768 токенов — около 85 000 символов. Звонок на 10 минут — около 3 500 токенов.

**Как изменить.**

1. В `config.yaml` задайте `context_tokens` у движка, например:

   ```yaml
   - id: mlx-d1-omni
     kind: mlx_local
     repo: LiquidAI/d1-Omni-2B-MLX-8bit
     context_tokens: 49152
     timeout_s: 90
     audio: true
   ```

   У каждого локального движка своё значение.
2. Перезапустите сервер.
3. Проверьте столбец «Контекст» в Матрице.
4. После увеличения запустите «Пробу» с галочкой «длинный» на этом движке. Она заполнит ~90 % нового предела и
   покажет время и то, читает ли модель его целиком.

При увеличении предела:

- Следите за свободной памятью: значения больше ~28K токенов на этом Mac не замерялись.
- Поднимите и `timeout_s`. Вызов на 28K токенов идёт ~28 с. Второй вызов, который ждёт за ним дольше `timeout_s`
  (30 с), получит `timed_out`.
- В dev-профиле whip-insight свой `context_tokens` (32 768). Держите его равным значению плейграунда.

Меньший предел бережёт память, а длинные звонки сразу получают `too_long`.

## 9. Compat-сервер для whip-insight

Compat-сервер отдаёт локальные d1 как `POST /v1/systemone` с именами System One. Он стартует с `make run`;
`make run-compat` запускает его одного.

### 9.1 Доступ

| Режим | `.env` | Кто может вызвать |
|---|---|---|
| Только этот Mac | `COMPAT_HOST=127.0.0.1` (по умолчанию), токен не обязателен | локальные процессы |
| LAN | `COMPAT_HOST=0.0.0.0` и `SYSTEMONE_TOKEN` | любой хост с токеном |

- Токен: не короче 32 символов, не меньше 10 разных; `openssl rand -hex 24` подходит. Без токена не-loopback
  `COMPAT_HOST` не даёт процессу стартовать.
- Адрес для whip-insight — `http://<имя-mac>.local:8791/v1/systemone`. Экран «Локальные модели» показывает его вместе
  с режимом доступа, состоянием токена и моделью по умолчанию.
- `compat.default_model` в `config.yaml` берётся, когда в запросе нет поля `model`. `model` принимает id движка,
  например `mlx-d1-omni`.

Проверка из папки репозитория:

```bash
curl -s http://127.0.0.1:8791/v1/systemone -H "Authorization: Bearer $SYSTEMONE_TOKEN" \
  -H 'Content-Type: application/json' -d @tests/fixtures/requests/whip_insight_systemone.json
```

`GET /health` не требует токена. Он возвращает `status` (`ok`, `degraded` после ошибки модели, `unavailable`), id и
состояние модели по умолчанию и версию mlx-vlm.

### 9.2 Контракт и ответы

- Типы: `noul`, `choice`, `score`. Для `multi`, `text`, `number`, `date` нужен заголовок
  `X-Playground-Extensions: 1`; whip-insight его не шлёт.
- 1–64 вопроса; тело до 6 МБ; до 4 картинок, каждая до 16 Мп. Поле `media` (аудио) отклоняется.
- В ответе — датированный снимок, `provider: "local-mlx"` и `usage.cost: 0`.

| Код | `error.code` в теле | Причина |
|---|---|---|
| 400 | `unsupported_question_type` | тип вне принимаемых; тело называет тип и вопрос |
| 400 | `forbidden_host` | заголовок Host не входит в `compat.allowed_hosts`; добавьте туда IP Mac, если клиенты ходят по нему |
| 401 | — | нет токена или токен неверный |
| 403 | — | в запросе есть заголовок `Origin` (страница браузера) |
| 404 | `model_not_found` | неизвестный `model` |
| 413 | `too_long` | запрос больше `context_tokens` (§8.2) |
| 429 | `busy` | ждут больше 8 вызовов, ожидание дольше `timeout_s` или сервер останавливается |
| 503 | `model_unavailable` | модель не скачана, не загружается или у неё сломан токенизатор |

## 10. Бюджет и стоимость

- `DAILY_BUDGET_USD` в `.env` (по умолчанию 1.0) — дневной лимит на платные вызовы. Локальные модели бесплатны.
- Перед каждым прогоном — оценка: (1.5 × символов state и вопросов + 200) × цена входа. Коэффициенты — `budget` в
  `config.yaml`. Модель без цены в каталоге берёт самую высокую цену decision-моделей каталога, иначе $0.20 за
  миллион токенов.
- Прогон, у которого оценка больше остатка, не запускается: «Оценка … больше остатка бюджета …».
- Факт — `usage.cost` от провайдера, иначе токены × цена каталога.
- Траты относятся к дню сохранения прогона. Прогон набора может превысить день не больше чем на один вызов на платный
  движок.
- Чтобы продолжить сегодня, поднимите `DAILY_BUDGET_USD` и перезапустите сервер.

## 11. Где лежат данные

| Папка | Содержание |
|---|---|
| `runs/<день>/<id>.json`, `runs/index.jsonl` | записи прогонов с текстами звонков и их индекс |
| `datasets/<имя>/` | `dataset.yaml` и `items.jsonl` |
| `probes/` | профили движков, кеш каталога, даты снимков локальных моделей |
| `reports/` | отчёты наборов, Markdown и JSON, без текстов звонков |
| `media/` | загруженные аудио и картинки |

- Эти папки в `.gitignore`; `DATA_DIR` в `.env` переносит их корень.
- Облачные вызовы уходят в OpenRouter с ZDR и `data_collection: deny`.
- Черновик Workbench — копия звонка в `localStorage` браузера; `make clean-runs` его не удаляет.
- `make clean-runs` и `make clean-media` удаляют `runs/` и `media/` после подтверждения.

## 12. Неполадки

### 12.1 Движок недоступен

| Причина на экране | Что сделать |
|---|---|
| `OPENROUTER_API_KEY is not set in .env` | задать ключ, перезапустить |
| `disabled in config.yaml` | `enabled: true` у движка, перезапустить |
| `<repo> is not downloaded: make models` | `make models` |
| `mlx-vlm is not installed (requirements-mlx.txt)` | `make setup` на Apple Silicon |
| `mlx-vlm X < 0.7.11` | обновить mlx-vlm в `.venv` (`requirements-mlx.txt`) |
| `needs macOS on Apple Silicon` | локальные модели работают только там (README, «Другие платформы») |
| `engine kind … arrives in …` | запланированный вид движка (WI-1) |

### 12.2 Классы отказов в результате

| Класс | Уровень | Причина и действие |
|---|---|---|
| `unsupported` | вопрос | движок не обслуживает этот тип (профиль или вид движка); выберите другой движок |
| `refused` | вопрос | модель отказалась отвечать |
| `invalid_answer` | вопрос | ответ не прошёл проверку (сумма вероятностей, неизвестный вариант) |
| `too_long` | запрос | больше предела: `context_tokens` (§8.2), `max_request_bytes`, лимит провайдера, B² реплик указателя |
| `rate_limited` | запрос | HTTP 429 от провайдера; очередь локальной модели заполнена |
| `timed_out` | запрос | нет ответа вовремя; у локальной модели ожидание в очереди дольше `timeout_s` |
| `unreachable` | запрос | нет соединения; локальная модель не скачана или не загружается |
| `provider_error` | запрос | 5xx после повтора, нечитаемый ответ, сбой движка |
| `budget` | запрос | не отправлен: дневной бюджет кончился |
| `refused` | запрос | другие 4xx; правила медиа или ZDR |

### 12.3 Другие сообщения

| Сообщение или симптом | Причина и действие |
|---|---|
| «Поток оборвался без итога» | соединение прервалось; откройте Историю, прогон мог сохраниться |
| «Каталог не обновился» | нет сети до OpenRouter; работает кешированный каталог |
| «WARNING: other users can read .env» при старте | `chmod 600 .env` |
| Загрузка отклонена с 503 | нет ffmpeg: `brew install ffmpeg` или `FFMPEG_BIN` в `.env` |
| HEIC или AVIF отклонены | сохраните картинку как JPEG или PNG |
| Указатель отклонён с 400 | в запросе есть медиа; указатель читает только текстовые реплики |
| «устарел» в Матрице | профиль другой версии модели; повторите пробу |
| Первый локальный вызов медленный | модель загружается; дальше вызовы быстрые до выгрузки по простою |
